# 第二工位扫描路径配置说明

> **文档版本**：v1.1  
> **更新日期**：2026-07-17  
> **配置文件目录**：`config/scan_paths/`  
> **加载入口**：`config.ini [Station] scanPathsConfigPath` 或 `station_profiles/*.ini`

---

## 1. 用途

`scan_paths` JSON 定义分段扫描的**全局段号（pointIndex）**与采集策略。IPC 按段号查配置后调用 `VisionPipelineService::requestCaptureBundle` 执行组合采集。

**触发分离（重要）**：扫描机械臂外部点位与伸缩杆内部扫描**不能共用同一触发**：

| 执行机构 | PLC 触发 | segmentKind |
|----------|----------|---------------|
| 扫描机械臂（外部 + 转台） | `Trig_ScanSegment`（40023） | `external` |
| 伸缩杆（内部纵缝/环缝） | `Trig_TelescopicScan`（40046） | `internal_*` |

段号按设备分寄存器：机械臂读 `AO47`/`40015`，伸缩杆读 `AO48`/`40016`（均为单字）；采集结果写入各自的 Ack/Res 与 Done 寄存器组。

| 模式 | 默认配置文件 |
|------|----------------|
| 圆筒半成品 `MODE_CYLINDER_SEMI` | [`station2_cylinder_semi.json`](../../config/scan_paths/station2_cylinder_semi.json) |
| 联调最小集 | [`station2_placeholder.json`](../../config/scan_paths/station2_placeholder.json) |
| 封头 / 成品 | 暂共用 placeholder，后续按模式拆分 |

## 2. JSON 结构

```json
{
  "version": "1.2",
  "lastModified": "2026-07-17",
  "activePathId": 1,
  "scanPaths": [
    {
      "pathId": 1,
      "enabled": true,
      "name": "straight_weld",
      "description": "直焊缝检测：AO47×10 + AO48×7",
      "devices": [
        { "device": "arm", "totalPoints": 10 },
        { "device": "telescopic", "totalPoints": 7 }
      ]
    }
  ]
}
```

### 2.1 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `activePathId` | 否 | **当前运行路径**（方案 A）。`>0` 时采集段号校验与 Inspection 配额**仅取该 path**；改配置后重启 IPC 即可切换。`0` 或省略时回退为汇总所有 `enabled` 路径 |
| `pathId` | 是 | 路径 ID，全局唯一 |
| `enabled` | 否 | 默认 `true`；无 `activePathId` 时参与配额汇总；有 `activePathId` 时主要用于文档/回退 |
| `name` | 否 | 稳定短名（如 `straight_weld`），日志与 HMI 展示 |
| `algorithm` | 否 | 检测算法：`weld_section`（直焊缝/环缝）/ `code_read` / `thickness_inner_surface`；空则按 `name` 推断 |
| `segmentKind` | 否 | 段类型，默认 `external`；后续可扩展 `internal_longitudinal` / `internal_ring`（伸缩杆/滚轮） |
| `description` | 否 | 说明文字，仅日志/文档用 |
| `devices[]` | 推荐 | `{ device: "arm"\|"telescopic", totalPoints: N }` 设备配额 |
| `totalPoints` | 条件 | 本路径点位数量；有 `devices` 时由配额自动求和 |
| `points[].pointIndex` | 条件 | **设备内本地段号**，与对应设备的 PLC 段号寄存器一致（臂 AO47 / 伸缩杆 AO48） |
| `points[].needRotation` | 否 | `true` → 预留彩色/2D 扩展；当前 Orbbec 主流程均采集深度+点云 |
| `points[].purpose` | 否 | 点位用途：`thickness_inner` / `thickness_outer` / `inner_surface` / `thickness`（两两配对）；供 Inspection 算法路由 |

### 2.2 校验规则（`ConfigManager::validateScanPathsConfig`）

- 路径 `pathId` 不重复
- `activePathId > 0` 时必须在 `scanPaths` 中存在对应路径
- `totalPoints` 与 `points` 数量一致（旧版无配额时）
- 活跃路径（或无 `activePathId` 时的已启用路径）须配置有效设备点数
- 显式点表中 **`pointIndex` 不重复**且大于 0

### 2.3 `scanSegmentTotal`

HMI：
- `status.system.scanPathProgress.currentPathId/Name` — **基础显示当前路径**（连接后与路径事件后刷新）
- `event.path.started` / `event.path.finished` — 路径开始/完成
- `status.plc.activePathId` / `activePathName` / `activePathAlgorithm` — 与上交叉校验
- `status.plc.scanSegmentTotal` 与 StateMachine 任务上下文取 **`enabledScanPointCount()`**（有 `activePathId` 时为该路径配额之和）。另推送 `armPointCount` / `telescopicPointCount`。若 JSON 未加载或为空，回退 `config.ini [Tracking] scanSegmentTotal`。

## 3. 运行时行为（已实现）

```text
PLC Trig_ScanSegment / Trig_TelescopicScan + segmentIndex
  → findScanPointByIndex + segmentKind 校验（外部/内部触发与路径类型须匹配）
  → requestCaptureBundle（按 needRotation 选 2D+3D / 3D）
  → 成功：内存缓存 + 落盘 output/run_{taskId}_{timestamp}/
  → Res=1，写对应 Done 寄存器组，推送 event.scan.*
```

### 3.1 落盘目录

单次运行实例共用一个目录（与 exe 同级的 `output/` 下），按 **运行实例 / 路径 / 机械臂|伸缩杆 / 点索引** 存放：

```text
output/run_{taskId}_{yyyy_MM_dd_HH_mm_ss_zzz}/
  path_{pathId}/
    arm/
      {pointIndex}/
        Path{pathId}_Arm_cloud_{pointIndex}.ply              # 原始点云 binary：xyz + uchar rgb
        Path{pathId}_Arm_cloud_stitched_{pointIndex}.ply     # LB 拼接后点云（仅 LB 成功变换时）
        Path{pathId}_Arm_texture_{pointIndex}.png
        Path{pathId}_Arm_hikC_{pointIndex}.bmp
        Path{pathId}_Arm_hikA_{pointIndex}.bmp        # 若启用 CXP
        Path{pathId}_Arm_hikB_{pointIndex}.bmp
        Path{pathId}_Arm_rt_global_{pointIndex}.txt   # 若调用 LB：4×4 行主序 Rt_global（IPC 作 T0）
        Path{pathId}_Arm_diagnostic_{pointIndex}.txt  # 可选，LB 诊断明细
    telescopic/
      {pointIndex}/
        Path{pathId}_Telescopic_cloud_{pointIndex}.ply
        Path{pathId}_Telescopic_cloud_stitched_{pointIndex}.ply
        ...
```

- **一次运行只创建一个 `run_*`**：切路径只清内存段缓存，不新建 run 目录；`Trig_ResultReset` 才会解绑并在下次采集新建。
- PLC `taskId=0` 时也复用已有 `run_0_*`，避免每段/每路径再开文件夹。
- 产物文件名统一为 `Path{pathId}_{Arm|Telescopic}_{产物}_{pointIndex}.ext`（例：`Path3_Arm_cloud_1.ply`），便于脱离目录也能识别。
- 点云 PLY 仅含 `x,y,z` 与 `red,green,blue`；有 Mech 纹理时按点序写入灰度 RGB。
- LB 成功时：`cloud` 为原始云，`cloud_stitched` 为按 Rt_global 变换后的拼接云（与工位一 `pointcloud_raw` / `pointcloud_stitched` 对应）；内存检测仍用拼接云。
- `rt_global` / `diagnostic` 与点云、BMP 平铺在同一点位目录（无 `lb_pose/` 子目录）；LB 失败时仍写 meta（`success=0`），无有效矩阵时不写数值块。

### 3.2 段缓存

- 每段采集成功后写入 `ScanSegmentCache`（内存），供后续 `Trig_Inspection` 读取（**待实现**）
- 切路径调用 `clearScanSegmentCacheForPathSwitch()`（保留 run 目录）
- `Trig_ResultReset`（两工位通用）：`executeResultResetTask()` 清空并解绑 run 目录、清路径进度/检测标记/编号软等待，并将 `activePathId` 复位到首条 enabled；后续段号 1 按该路径处理

### 3.3 Res 码（ScanSegment）

| Res | 含义 |
|-----|------|
| 1 | 采集成功 |
| 5 | 段号不在 scan_paths 中 |
| 6 | 任务超时 |
| 7 | 视觉采集失败 / 流水线不可用 |

失败清理（`[FlowControl] scanFailurePolicy`，默认 `segment`，与工位1一致；亦可读 `[Resume] scanFailurePolicy`）：

| 策略 | 行为 |
|------|------|
| `segment` | 仅从内存缓存剔除失败本段（臂/伸缩杆本地段号），其它已扫段保留 |
| `path` | 清当前路径全部段缓存，保留 `run_*` 目录绑定 |
| `workpiece` | 整表清零并解绑 `run_*`，路径回首条 enabled（近似 `ResultReset` 缓存侧） |

`Res>=5`、段扫超时、故障中止段扫时生效。`Trig_Inspection` 超时：`workpiece`/`path` 同上；`segment` 保留段缓存供重试，且不把超时标成「已检测」。

---

### 3.4 Res 码（Inspection）

| Res | 含义 |
|-----|------|
| 1 | OK（`algorithm=weld_section`：焊缝截面测量通过） |
| 2 | NG（段 bundle 无效 / 点云无效 / 算法失败） |
| 3 | 需人工复检（无缓存 / taskId 不一致 / 段数不足 / 算法未接入） |
| 6 | 任务超时 |

流程：

```text
PLC Trig_Inspection
  → InspectionHandler → evaluateInspectionForActiveTask
  → 按 activePath.algorithm 路由：
       weld_section → WeldMeasure（path1 直焊缝 / path5 环缝）
       length_volume → ContainerTotalLength（path3；臂×8 合并外表面云，IPC 补算容积）
       thickness_inner_surface → Thickness + InnerSurface（path4；按 purpose 配对）
       code_read → 海康 C NumberRecognition OCR（亦可用 Trig_CodeRead）
       其它 → Res=3 明确未接入
  → finishInspection → writeInspectionResult + Res
  → publishInspectionResult → event.inspection.finished（含 pathId/pathName/algorithm）
```

HMI 调试：`cmd.debug_trigger_inspection` 仅评估缓存并推送，**不写 PLC**。

切换路径（方案 A）：改 JSON `activePathId` 后重启 IPC；切路径后建议 PLC 先 `Trig_ResultReset` 清段缓存再采新路径。

**运行时路径切换（v0.3.1，推荐）**：PLC **只需写** `ScanPathId(40047)`，不必读回显。

| 寄存器 | 方向 | PLC 要做吗 | 含义 |
|--------|------|------------|------|
| `40047` ScanPathId | PLC→IPC | **要写** | 当前 `pathId`（1 起；0=未指定，IPC 沿用当前） |
| `40185` ScanPathIdEcho | IPC→PLC | **不用读** | 可选回显，仅 HMI/调试 |

约定：相关 Trig 置 1 **之前**写好 `ScanPathId`；`pathId` 变化时 IPC 清段缓存并切换，**不再**用“段号 1 = 新周期”猜测切路。

兼容（旧，未写 40047 时）：以下仍可能自动切路：
1. `Trig_Inspection` / `Trig_CodeRead` 成功（Res=1）
2. 当前路径扫描齐套后，PLC 再次下发本地段号 `1`
